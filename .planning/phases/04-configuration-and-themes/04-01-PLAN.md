   b. `CustomThemeColors` struct (mirrors ThemeColors from theme.rs for TOML deserialization) with `#[derive(Debug, Clone, Deserialize)]` and `#[serde(default)]` on each field. All fields `Option<String>`:
      - `editor_bg`, `editor_fg`, `line_number_fg`, `selection_bg`
      - `search_active_bg`, `search_active_fg`, `search_match_bg`, `search_match_fg`
      - `divider_fg`, `status_bar_bg`, `status_bar_fg`
      - `confirm_bg`, `confirm_fg`, `prompt_bg`, `prompt_fg`
      - `syntect_theme`

   c. `Config` struct with `#[derive(Debug, Clone, Deserialize)]` and `#[serde(default)]`:
      - `theme: String` (default `"ocean"` per D-05)
      - `mode: EditingMode` (default `Vim` per D-11)
      - `custom_themes: std::collections::HashMap<String, CustomThemeColors>` — maps to TOML `[custom_themes.mytheme]` sections (per D-10)

   d. Implement `Default` for `Config`: `theme = "ocean"`, `mode = EditingMode::Vim`, `custom_themes = HashMap::new()`.

   e. Implement `pub fn load_config() -> Config`:
      - Use `dirs::config_dir()` to get platform config dir (per D-01)
      - Append `mdedit/config.toml` to get full path
      - If file does not exist, return `Config::default()` (per D-02)
      - If file exists, read it with `std::fs::read_to_string`
      - Deserialize with `toml::from_str::<Config>(&contents)`
      - On deserialization error: print warning to stderr `eprintln!("Warning: failed to parse config: {err}, using defaults")` and return `Config::default()` (per D-02)

   f. Implement `pub fn resolve_theme(config: &Config) -> Theme`:
      - Try `Theme::by_name(&config.theme)` first
      - If None, check `config.custom_themes.get(&config.theme)` — if found, create theme with `Theme::from_custom(&Theme::ocean(), custom_colors)` where custom_colors is converted from the CustomThemeColors
      - If neither matches, print warning `eprintln!("Warning: unknown theme '{}', using ocean", config.theme)` and return `Theme::ocean()`

2. Update `src/main.rs`:

   a. Add `mod config;` and `mod theme;` module declarations.

   b. Add CLI args to the `Cli` struct (per D-06, D-12):
      - `#[arg(long)] theme: Option<String>` — override theme name
      - `#[arg(long)] mode: Option<String>` — override editing mode ("vim" or "nano")

   c. In `main()`, after CLI parsing:
      - Call `let mut config = config::load_config();`
      - If `cli.theme.is_some()`, override: `config.theme = cli.theme.unwrap();`
      - If `cli.mode.is_some()`, parse and override: match on "vim" -> `config.mode = config::EditingMode::Vim`, "nano" -> `config.mode = config::EditingMode::Nano`, other -> `eprintln!("Warning: unknown mode '{}', using vim", mode)`
      - Call `let mut resolved_theme = config::resolve_theme(&config);`
      - Detect color: `let cap = theme::detect_color_capability();` — if `Color256`, call `resolved_theme = resolved_theme.with_256_color_fallback();`
      - Pass `resolved_theme` and `config.mode` to `App::new()` — update `App::new` signature to accept `theme: Theme, mode: EditingMode` as additional parameters (store them in App struct but don't wire to rendering yet — that's Plan 02)
      - Update `App::new()` to accept and store `theme: theme::Theme` and `editing_mode: config::EditingMode` fields. The `editing_mode` is stored but unused until Phase 5 (per D-11). The `theme` is stored for wiring in Plan 02.

3. Add `pub editing_mode: config::EditingMode` and `pub theme: theme::Theme` fields to `App` struct. Initialize them from the new parameters in `App::new()`.
